# Encoding standards into the system

You want agents and distributed builders to make the same decisions you
would. The goal is standards encoded into the means of production, so the
system scales intent rather than just consistency. Apply the rules in order.

## 1. The object of design is the system, not the screen

Interfaces are now built without a designer in the room; agents find and fix
problems while you sleep; UI is generated in real time for users. You can't
be part of every decision, so the standard has to live where the decisions
get made — in the system itself.

## 2. Scale intent, not just consistency

The old system scaled consistency: everyone used the same components. The
new one must scale intent: extensible *and* opinionated enough that
machine-made output feels handmade. Gutenberg didn't cut 26 letters; he cut
290 characters with widths and ligatures so typeset pages kept the beauty of
handwork. Aim for the same — flexible enough to build with, opinionated
enough to stay yours.

## 3. Put standards into the means of production

A bare hook that reads your docs is not specific enough: three people put in
the same prompt and get three results. Build a harness — a CLI, templates,
anything the builders actually build with — that consumes the documentation
at the right time and place, so the standard arrives where it's needed
instead of rotting in context it never matched.

## 4. Encode flows, not just components

Components and atomic parts aren't enough. The system has to know how the
product is supposed to behave and how it all comes together — full templates
and flows, not just pieces. When the system understands the whole, the
outputs stay coherent no matter who or what assembles them.

## 5. Make the decisions easy to define

There is no longer always a human in the room to fill in the blanks, so the
decisions themselves need to be explicit and easy to state. Write the
standards down as rules an agent can follow, not as taste a person would
have to carry.
