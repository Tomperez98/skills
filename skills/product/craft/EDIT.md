# Editing: refuse to confuse done with good

You have something that's "done" — generated fast, looks polished — and you
need to know whether it's actually good. The goal is to edit it like an
owner, not a reviewer. Apply the rules in order.

## 1. Unlearn that built means done

The filter used to live throughout the process — twenty ideas, staff one,
prune as you go. Now you can build twenty ideas in a week, so the filtering
moves to *after* the build, when it's much harder to say no. Built is not
done, and done is not good. Someone has to be the editor; name who.

## 2. Experience it like a user would

Step out of the builder's seat. Does it actually solve the problem? Is it
attuned to how the user thinks about it? Is it coherent? Most things look
good in isolation and fall apart in the user journey — pull it together and
read it end to end the way a real person would.

## 3. Account for every decision — every pixel

An editor takes accountability for every detail. The tell of AI slop is that
the details don't matter — the cup is green but may as well have been blue.
Scrutinize pixel by pixel: if a detail could be anything, it shows no one
decided.

## 4. Push toward completion, not just a verdict

Editing is not a yes/no gate. Ask whether the thing is even fully formed,
and push it to completion. "Done" must not be the enemy of "good" — the
goal is to get it all the way there, not to stamp it and move on.

## 5. Iterate past the first plausible result

The first version is cool and fun, but scrutinized it's slightly off — the
motion's jilted, the framing's wrong. Do it again and again. Fifty-six
iterations later the care is visible in the subtle differences. AI lowers
the cost of each attempt; spend that on the iterations that get it right.
