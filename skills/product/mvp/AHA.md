# Finding the five-minute "aha"

You have a specific idea. The goal is to strip it to the one core use case
and the shortest journey to real value. Apply the rules in order.

## 1. Name the one core use case

Every idea has one main use case — the thing most people will open the app
to do. Say it in one sentence. If you can't name a single main use case, you
haven't found it yet; keep looking.

## 2. Cut the feature list

Don't add a bunch of features. Everything that isn't the core use case is
scope creep until the core one is validated. If a feature doesn't serve the
one use case, delete it for now — you can bring it back after someone real
hits the aha.

## 3. Define the core experience

Ask: what is the core experience, and how does the user get value quickly?
The answer is a moment, not a menu — the single interaction where the payoff
lands. "A photo that comes back with lines on it" is a core experience;
"a dashboard of metrics" is a menu.

## 4. Draw the five-minute journey

Consumers have almost no attention span — they'll give a new app about five
minutes. Map the journey from open to value, and cut anything that pushes
the aha past that window. Every extra step before the payoff costs users.

## 5. The aha is the milestone

The aha — the five-minute value moment — is your MVP, not the feature list.
Once a user can reach it, you have an MVP; everything else waits.

## 6. One journey, not a tour

Resist adding a second use case "while you're here." The MVP is a line, not
a tour. The tour comes after the first use case is validated (see
[VALIDATE.md](VALIDATE.md)).
