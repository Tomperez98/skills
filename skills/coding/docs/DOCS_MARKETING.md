# Docs-as-marketing: making docs acquire and convert

Your docs are your best marketing, because a developer trusts a working
example more than any ad. This file is about the docs *as* a growth channel:
making them findable, shareable, and able to convert a reader into a trier.
Apply the rules in order.

## 1. One page, one search intent

Each page targets one thing a developer actually types into a search box,
and the title says it in those words. "How to retry a failed request" beats
"retry — retry failed operations" beats "The retry module." Write the page
for the person whose query you want to win, then make the page the best
answer to it.

## 2. Make the page self-sufficient and shareable

A developer shares a page when it stands alone: the context, the example,
and the result are all on the page, so a link is enough to make sense of it.
Pages that require clicking through five others never get shared. Every page
should read like a blog post someone would send to a colleague.

## 3. The example is the ad

Your copy-paste example is the single most persuasive thing you ship. Make
it complete (runs as pasted), real (a task the reader actually has), and
short enough to fit in one screen. A reader who pastes it and it works has
just had your best sales conversation — with zero sales.

## 4. Convert at the moment of success

The moment the example works is the moment the reader is most ready to act.
Put the conversion there, not in a banner: "this worked? here's how to
install it / use it in your stack / read the next page." The CTA is a next
step in their task, not a pitch.

## 5. Rank on the tasks you want to own

Target the task queries where your docs genuinely win — the ones your
product does unusually well. Don't chase generic terms where you'd lose; own
the long tail of "how do I do X with Y" where your example is the answer.
Write it to be the best answer, and the rank follows — never clickbait to
get there: the title's promise must be delivered in the first scroll, so a
visitor who lands on a search hit gets what they clicked for.

## 6. Measure what resonates

Watch which pages get read, which examples get copied, and which pages
precede a signup — not vanity pageviews. The pages that convert tell you
which tasks to write more about; the pages that get read but don't convert
tell you where the example isn't carrying its weight.

## 7. Reuse the artifact everywhere

One great tutorial is a landing page section, a changelog entry, a launch
post, and a docs page. Write the example once, then repurpose it across
surfaces with the framing each surface needs — the README leads with the
hero, the launch post leads with the story, the docs page leads with the
task.
